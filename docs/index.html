I attack my own network, then write down what my SIEM missed.

A five-VLAN enterprise-style lab on one Proxmox host, built with free tools. I attack it from Kali, hunt the attack in Wazuh, work it as a DFIR-IRIS case and document every rule. Gaps are written up as findings with root causes, not hidden.

What this demonstrates

Detection engineering

Custom Wazuh XML rules with parent chains, frequency correlation and regex tuning. Alerts are tuned per rule, never by global threshold. One rule went from 393 hits to 1 true positive, then was re-proved on live traffic.

Purple teaming

Real techniques run from Kali against AD and Docker targets, then hunted in the SIEM. Blue-team write-ups are done without the attack playbook open, so the detection story can't lean on knowing the answer.

SOC operations and incident response

SIEM, IDS, endpoint telemetry and case management as one pipeline. Every scenario becomes a DFIR-IRIS case with assets, IOCs, timeline and tasks. Two dashboards are built for a morning triage review.

DFIR-IRIStriageIOCsSuricatadashboardscredential rotationdetections/wazuh-dashboards

Network segmentation and Active Directory

Five VLANs behind pfSense with default-deny rulesets and scoped temporary rules for testing. Two Server 2025 DCs, GPOs, a NIST 800-63B password policy, and deliberately roastable service accounts to exercise detections.

pfSenseleast privilegeActive DirectoryGPONIST 800-63Bfirewall-rules/

Segmented zones, default-deny between them

Telemetry flows one way into the SOC. The attacker VLAN is blocked from the corporate and security zones unless I open a scoped, temporary rule for a test.

Lessons carry forward

The ::ffff: lesson shaped Scenario 02's rule, which worked first time live. Scenario 03's blind spot became rules 100170–100173.

Alert before lockout

Windows brute force alerts at 4 failures because AD locks at 5, so the SOC sees it before the helpdesk ticket.
